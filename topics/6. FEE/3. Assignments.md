## **ASSIGNMENT 01: STATIC DASHBOARD**

_(For Session 2)_

**Objective:** Build the Layout using Semantic HTML & CSS (No JS yet).

**Deliverables:**

- A responsive HTML/CSS page `index.html` (and `styles.css`).
- It must look professional (Clean UI).

**Requirements:**

1. **Header:**
   - App Logo/Name (left).
   - Navigation Links (right).

2. **Main Content (Student List Table):**
   - Table columns: ID, Name, Email, DOB, GPA, Status (Active/Graduated).
   - Actions column: "Edit" and "Delete" buttons.
   - "Add New Student" button on top.

3. **Modal/Form (Hidden by default or separate page):**
   - Form fields: Name, Email, DOB.
   - Buttons: Save, Cancel.

4. **Responsive:**
   - On Mobile: Hide the less important columns (e.g., DOB, Email). Table should scroll horizontally if needed.

> **Critical Thinking:**
>
> - Why use `class` instead of `id` for styling?
> - How to make the Modal appear/disappear using CSS only (optional challenge: `target` pseudo-class) or prepare it for JS?

## **ASSIGNMENT 02: CONNECTING TO BACKEND**

_(For Session 4)_

**Objective:** Make the page alive effectively consuming your own Spring Boot API.

**Prerequisites:**

- Your Spring Boot App (Topic 5) must be running at `http://localhost:8080`.
- **CORS:** You might need to enable CORS in Spring Boot (`@CrossOrigin(origins = "*")` on Controller) to allow requests from your HTML file (which might run on `file://` or `http://127.0.0.1:5500`).

**Requirements:**

1. **Read (GET):**
   - On page load (`DOMContentLoaded`), fetch the list of students from `http://localhost:8080/api/v1/students`.
   - Clear the hardcoded HTML rows.
   - Loop through data and append rows dynamically to the table.

2. **Create (POST):**
   - When "Save" on the form is clicked:
     - Collect values from inputs.
     - Validate inputs (Client-side validation).
     - Send `POST` request with JSON body.
     - If success: Close modal + Refresh list.
     - If error: Show alert.

3. **Delete (DELETE):**
   - Attach Event Listener to "Delete" buttons.
   - Confirm with user (`confirm("Are you sure?")`).
   - Send `DELETE` request to `/api/v1/students/{id}`.
   - Remove the row from DOM upon success.

> **Critical Thinking:**
>
> - **CORS:** Why does the Browser block requests from `http://127.0.0.1:5500` to `http://localhost:8080` by default?
> - **Performance:** Is it better to re-fetch the whole list after adding a student, or just manually append the new student to the existing DOM list? Trade-offs?
